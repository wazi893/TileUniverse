# SPRINT 80: FPGA Synthesis Module

## Overview

SPRINT 80 introduces RustHDL-based FPGA synthesis capabilities to TileUniverse. This enables exporting tile-based circuit designs to synthesizable Verilog for deployment on physical FPGA hardware.

## Architecture

```
TileType (simulation) --> RustHDL LogicBlock --> Verilog --> FPGA Bitstream
     |                         |                    |
     v                         v                    v
  51 tile types         ~30 primitives      Grid synthesis
```

## Module Structure

```
src/fpga/
├── mod.rs              # Module root, traits, config types
├── types.rs            # TileTypeCode enum, propagation delays
├── primitives/
│   ├── mod.rs          # Re-exports all primitives
│   ├── combinational.rs # Wire, And, Or, Xor, Not, Cross tiles
│   ├── arithmetic.rs   # Add, Sub, Mul, Div, Shl, Shr, Neg, Abs
│   ├── comparison.rs   # Lt, Gt, Eq, Neq, Lte, Gte, Zero, Mux
│   ├── sequential.rs   # Register8, Latch, RegEnable, Ram, Counter
│   └── cpu.rs          # Decoder3to8, Mux8to1, Demux1to8, ProgramCounter
└── synthesis.rs        # Grid-to-Verilog transpiler
```

## Usage

### 1. Individual Primitives (RustHDL)

```rust
use engine::fpga::prelude::*;

// Create an AND gate
let mut and_gate = AndTile::default();
and_gate.connect_all();

// Generate Verilog via RustHDL
let verilog = generate_verilog(&and_gate);
```

### 2. Grid Synthesis

```rust
use engine::fpga::synthesis::{SynthesisGrid, SynthesisTile};
use engine::tiles::tile_meta::TileType;

// Create a 4x4 grid
let mut grid = SynthesisGrid::new(4, 4);

// Place tiles
grid.set(0, 0, SynthesisTile {
    tile_type: TileType::And,
    initial_value: 0,
});
grid.set(1, 0, SynthesisTile {
    tile_type: TileType::Register8,
    initial_value: 0,
});

// Generate Verilog
let verilog = grid.to_verilog();

// Resource estimation
let resources = grid.estimate_resources();
println!("LUTs: {}, FFs: {}", resources.luts, resources.flip_flops);
```

## Implemented Primitives

### Routing (6 tiles)
| Tile | Logic | Delay |
|------|-------|-------|
| Wire | `out = left \| right \| up \| down` | 1 |
| WireH | `out = left \| right` | 1 |
| WireV | `out = up \| down` | 1 |
| WireDown | `out = up` | 1 |
| WireRight | `out = left` | 1 |
| Cross | `out[31:0] = left\|right, out[63:32] = up\|down` | 1 |

### Logic Gates (4 tiles)
| Tile | Logic | Delay |
|------|-------|-------|
| And | `out = left & right` | 2 |
| Or | `out = left \| right` | 2 |
| Xor | `out = left ^ right` | 3 |
| Not | `out = ~left` | 2 |

### Arithmetic (9 tiles)
| Tile | Logic | Delay |
|------|-------|-------|
| Add | `out = left + right` | 5 |
| Sub | `out = left - right` | 5 |
| Mul | `out = left * right` | 8 |
| Div | `out = left / right` | 12 |
| Mod | `out = left % right` | 12 |
| Shl | `out = left << right[5:0]` | 3 |
| Shr | `out = left >> right[5:0]` | 3 |
| Neg | `out = -left` | 5 |
| Abs | `out = left[63] ? -left : left` | 5 |

### Comparison (7 tiles)
| Tile | Logic | Delay |
|------|-------|-------|
| Lt | `out = (left < right) ? MAX : 0` | 4 |
| Gt | `out = (left > right) ? MAX : 0` | 4 |
| Eq | `out = (left == right) ? MAX : 0` | 4 |
| Neq | `out = (left != right) ? MAX : 0` | 4 |
| Lte | `out = (left <= right) ? MAX : 0` | 4 |
| Gte | `out = (left >= right) ? MAX : 0` | 4 |
| Zero | `out = (left == 0) ? MAX : 0` | 3 |

### Sequential (7 tiles)
| Tile | Logic | Delay |
|------|-------|-------|
| Register8 | `@(posedge clk) out <= left` | 0 |
| Latch | `@(posedge clk) out <= left` | 0 |
| RegEnable | `@(posedge clk) if (up && right[0]) out <= left` | 0 |
| Ram | `@(posedge clk) if (up) mem <= left` | 0 |
| Counter | `@(posedge clk) if (up) out <= out + 1` | 0 |
| Const | `out = constant_value` | 0 |
| ClockGlobal | Toggles output each clock | 0 |

### CPU Building Blocks (4 tiles)
| Tile | Logic | Delay |
|------|-------|-------|
| Decoder3to8 | `out = 1 << left[2:0]` | 2 |
| Mux8to1 | `out = left[right[2:0]*8 +: 8]` | 3 |
| Demux1to8 | `out = up[7:0] << (left[2:0]*8)` | 2 |
| ProgramCounter | `@(posedge clk) pc <= right[0] ? left : pc+1` | 0 |

## Generated Verilog Structure

```verilog
// Generated by TileUniverse FPGA Synthesis (SPRINT 80)
// Grid: 4x4

module tile_grid_4x4 (
    input wire clk,
    input wire rst_n,
    input wire [63:0] left_0,
    input wire [63:0] left_1,
    // ... boundary ports
    output wire [63:0] right_0,
    output wire [63:0] bottom_0
    // ...
);

    // Internal tile output wires
    wire [63:0] tile_0_0_out;
    wire [63:0] tile_1_0_out;
    // ...

    // Tile instances
    assign tile_0_0_out = left_0 & tile_1_0_out;  // AND
    reg [63:0] reg_1_0;                            // Register
    always @(posedge clk) reg_1_0 <= tile_0_0_out;
    assign tile_1_0_out = reg_1_0;
    // ...

endmodule
```

## Limitations

### Current Stub Implementations

Some primitives are simplified stubs awaiting full RustHDL patterns:
- **Not**: Uses passthrough (full NOT requires XOR with all-ones constant)
- **Comparison tiles**: Simplified to passthrough (need conditional in hdl_gen)
- **Mul/Div/Mod**: Passthrough stubs (complex operations)

These generate correct Verilog in the synthesis transpiler but the RustHDL simulation may not match.

### hdl_gen Macro Restrictions

RustHDL's `#[hdl_gen]` macro has strict requirements:
- Cannot use `!` operator (NOT)
- Field name `input` is reserved
- Conditional logic requires specific patterns
- No direct integer literals in some contexts

## Dependencies

```toml

version = "0.46"
optional = true
```

RustHDL provides:
- `LogicBlock` derive macro for automatic signal connection
- `#[hdl_gen]` for HDL-compatible update functions
- `Signal<In/Out, Bits<N>>` typed ports
- `DFF<T>` D flip-flops with `dff_setup!` macro
- Verilog code generation

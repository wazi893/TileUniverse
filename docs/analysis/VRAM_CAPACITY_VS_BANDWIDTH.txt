════════════════════════════════════════════════════════════════
THE CAR ANALOGY
════════════════════════════════════════════════════════════════

Think of VRAM like a highway:

VRAM CAPACITY (8 GB) = How many cars can FIT on the highway
  • 8 GB = 8 billion bytes worth of "parking spots"
  • Like a massive parking lot
  • More capacity = more stuff you can store

VRAM BANDWIDTH (504 GB/s) = How fast cars can MOVE on the highway
  • 504 GB/s = 504 billion bytes per second throughput
  • Like the speed limit + number of lanes
  • More bandwidth = faster data movement

Your situation:
  • You have parking for 8 BILLION cars (8 GB capacity)
  • But you only parked 8 MILLION cars (8 MB used)
  • The highway can move 504 BILLION cars/second (504 GB/s)
  • You're driving all 8M cars repeatedly at highway speed
  • You're maxing out the SPEED LIMIT, not the parking lot!

════════════════════════════════════════════════════════════════
YOUR CURRENT USAGE BREAKDOWN
════════════════════════════════════════════════════════════════

Let's see exactly where your 8 MB is going:

1024 states × 12 qubits configuration:
  • Amplitudes: 1024 states × 4096 amps × 2 bytes = 8,388,608 bytes
  • That's 8 MB for the quantum state data

Additional VRAM usage:
  • Gate matrices: 16×16 × 2 bytes = 512 bytes (negligible!)
  • CUDA context: ~500 MB (driver, kernel code, etc.)
  • Buffers/scratch: ~100 MB (temporary workspace)
  • Total: ~608 MB actual VRAM usage

Available: 8 GB = 8,192 MB
Used: ~608 MB
Free: ~7,584 MB (92% unused!)

So you're not just using 8 MB, you're using ~608 MB total, but the
STATE DATA is only 8 MB. The rest is overhead.

════════════════════════════════════════════════════════════════
WHY USING MORE CAPACITY DOESN'T HELP SPEED
════════════════════════════════════════════════════════════════

Key insight: CAPACITY and BANDWIDTH are independent!

Example 1: Small data, bandwidth saturated (YOUR CASE)
────────────────────────────────────────────────────────
  • Data size: 8 MB
  • You process it 1,000,000 times (depth)
  • Memory traffic: 8 MB × 1M = 8 TB moved!
  • Bandwidth: 504 GB/s
  • Time: 8 TB / 504 GB/s = 15.87 seconds
  • Capacity used: Only 8 MB (0.1%)
  • Bandwidth used: 100% SATURATED! 🔥

Example 2: Large data, bandwidth not saturated
────────────────────────────────────────────────────────
  • Data size: 4 GB (half of VRAM)
  • You process it 1 time
  • Memory traffic: 4 GB moved
  • Bandwidth: 504 GB/s
  • Time: 4 GB / 504 GB/s = 0.008 seconds
  • Capacity used: 50%
  • Bandwidth used: <1% (barely touched!)

The pattern:
  • Small data × many iterations = bandwidth saturated
  • Large data × few iterations = capacity matters more

Your workload: SMALL DATA, MANY ITERATIONS
→ Bandwidth is the bottleneck, not capacity!

Strategy 4: DOUBLE BUFFERING
────────────────────────────────────────────────────────
Use VRAM to HIDE latency:

  • Buffer A: 8 MB (currently processing)

  • Buffer C: 8 MB (previous batch, results)

  • Async copy next batch to buffer B
  • Overlap everything!

  • Everything stays on GPU
  • No PCIe transfers
  • This doesn't help! ✗

Strategy 5: CACHE INTERMEDIATE RESULTS
────────────────────────────────────────────────────────
For complex circuits, cache expensive intermediate states:

Example: Applying sequence H → X → CNOT → H
  • Compute H|ψ⟩, cache result (8 MB)
  • Compute X(H|ψ⟩), cache result (8 MB)
  • Compute CNOT(X(H|ψ⟩)), cache result (8 MB)
  • Reuse cached results if needed
  • Total: 32 MB for 4 intermediate states

This helps IF:
  ✓ You reuse intermediate results multiple times
  ✗ Most quantum circuits don't reuse states

Not applicable to your current workload.
